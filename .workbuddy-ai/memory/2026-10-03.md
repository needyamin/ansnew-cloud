# 2026-10-03

## Bug: env vars silently ignored (ADMIN_PASSWORD etc.)

`src/App/Config/Config.php` populated `$this->values` from a hard-coded whitelist of
env keys. Any key not in that list read as `''` via `Config::get()`, so `.env` values
were ignored. Missing keys included `ADMIN_USER`, `ADMIN_PASSWORD`, `ADMIN_EMAIL`,
`APP_KEY`, `WS_SECRET`, `ANSNEW_FILE_KEY(_ID)`, `DEFAULT_MOUNT_PATH`, `DEFAULT_MOUNT_LABEL`,
`ANSNEW_ENCRYPT_LOCAL`, `ANSNEW_DATA_DIR`, `ANSNEW_STORAGE_ROOT`.

Consequences:
- Bootstrap admin always got a *random* password (printed once in php logs), even when
  `ADMIN_PASSWORD` was set.
- `WS_SECRET` mismatch risk: node (ws-server/server.js) reads `process.env.WS_SECRET`
  directly, PHP fell back to the generated `data/keys/ws.secret` file.

Fix applied: added all missing keys to the whitelist + a comment stating the rule.

## Follow-up: admin/admin made to work (dev only)

- `Validator::password()` min length is now configurable: `PASSWORD_MIN_LENGTH` env
  (Config whitelist), default 10. `.env` and `.env.example` set 5 so the local
  `admin/admin` account is accepted. **Remove that line for any real deployment.**
- `bin/console.php` reset-password note updated to use the configured minimum.
- README: env table row + corrected the "min 10 characters" wording.
- Existing admin already had a random password (bootstrap is one-shot), so the fix was
  applied with `ansnew:reset-password --user=admin --password=admin`, then verified:
  `POST /api/auth/login` -> ok, role=admin. Login needs a CSRF header: GET
  `/api/bootstrap` first and send `X-CSRF-Token` with the session cookie.

## Related gotchas (not code bugs)
- `ansnew:bootstrap-admin` is one-shot: it skips when the user already exists, so
  editing `ADMIN_PASSWORD` after first boot does nothing. Use
  `./ansnew reset-password --user=admin --password='...'`.
- `Validator::password()` rejects < PASSWORD_MIN_LENGTH (default 10). A short
  `ADMIN_PASSWORD` makes bootstrap throw -> "[ansnew] admin bootstrap deferred".
- `src/` is COPYed into the php/worker image, not bind-mounted -> any PHP change needs
  `docker compose build php worker && docker compose up -d`.
- With `DB_DRIVER=sqlite`, `DB_PASSWORD` is unused; for the mysql profile
  `MARIADB_PASSWORD` only applies on the first init of the `db_volume`.

## Desktop-grade file manager UI (frontend + backend overhaul)

Goal: no page refreshes after any operation, no flicker, instant feedback, preserved
location/selection/scroll, fewer API calls. All work verified against the running stack.

**Frontend**
- `api.js` rewritten as a real fetch layer: in-flight de-duplication, TTL cache with
  stale-while-revalidate, ETag/`If-None-Match` 304 handling, `AbortController` + timeout,
  and separate read/write concurrency lanes.
- `filespane.js` rewritten around **windowed rendering**: absolutely-positioned rows inside
  a `.fl-spacer`, node recycling, `view()` cache, `scrollToIndex()`, scroll anchoring.
  Only ~30 DOM nodes for a 1 501-entry folder. Two rules make recycling safe: bind
  listeners once per node (never per render) and never close over an entry — resolve it
  from `dataset.path` at event time.
- New `mutation.js`: `runOp()` optimistic orchestrator + `applyLocal()`/rollback on the
  pane; `watchJob()` bounded poll so a lost WS push can't leave rows dimmed forever.
- New `fswatch.js`: consumes `fs.changed` and silently revalidates affected panes.
- `refresh()`/`revalidate()` are now silent (no skeleton, no cleared selection, no scroll
  jump) and errors never blank the pane.
- Uploads: bounded 3-file worker pool, working cancel (threaded AbortController through
  both XHR and chunked paths), real completion callback, optimistic row insertion.
- Split view / details toggle no longer destroy and refetch both panes; sidebar is not
  rebuilt on every selection change.

**Backend**
- `GET /api/fs/{m}/list` returns an `ETag` (sha1 of name/type/size/mtime) and answers 304.
- New batch endpoints `delete-batch` / `move-batch` / `copy-batch` returning
  `{done, async, failed, skipped}` — one request per selection instead of one per item.
- `Kernel::finish()` no longer overwrites controller-set headers (it was killing every
  `Cache-Control`, making thumbnail caching dead code).
- Separate rate-limit bucket for `/thumb` (1200/60s) — a 500-photo folder used to trip the
  shared 240/60s limiter instantly.
- New `NotifyService` + `fs.changed` pushes from every mutation and from `bin/worker.php`.
- nginx: gzip enabled; `/assets/` now repeats the security headers (`add_header` in a
  location replaces inherited ones).

**Bugs fixed**: change-password always 403 (client sent `current`/`password`, server reads
`currentPassword`/`newPassword`); upload cancel was a no-op; upload completion fired at
start; double list fetch on every sidebar click; thumbnail observer disconnected globally;
`FilesPane.destroy()` never called; download-token polled forever; any finished job blanked
the pane; server-side into-itself move guard; logout did `location.reload()`.

**The subtle one**: `curl_exec()` without `CURLOPT_RETURNTRANSFER` prints the upstream
response into the output buffer. Harmless from the CLI worker, but once `NotifyService` ran
inside HTTP handlers it prepended `{"ok":true}` to every mutating API response. `res.json()`
then threw, the client swallowed it and returned `null`, so mutations looked fine while
silently returning no data. Fixed with `RETURNTRANSFER => true`; `realtime-test.mjs` now
asserts raw bodies are parseable.

**Tests added** (all self-contained): `tools/perf-smoke.mjs` (windowing/scroll/no-flicker),
`tools/optimistic-smoke.mjs` (instant rows, batch ops, rollback, uploads, no reloads),
`tools/realtime-test.mjs` (fs.changed per mutation type). `tools/js-import-check.mjs` now
also flags a sibling module's export being used without importing it — that class of bug
had silently broken every mutation once.

**Environment notes (not app bugs)**
- Host port 8080/8081 sit in a Windows Hyper-V reserved range (8031–8130), so compose can't
  publish them. The stack is run with `HTTP_PORT=8200 docker compose up -d`.
- Headless Chrome in this sandbox never receives page-level WebSocket frames (verified
  against a host-local WS server). `optimistic-smoke.mjs` probes and skips its realtime
  assertions; `realtime-test.mjs` covers that ground from Node.
- Test suites that create `ui-smoke-*` folders leave them behind, which eventually pushes
  new rows below the fold. `storage-root/` was cleaned back to empty; keep it that way.
